# Feature Specification: Add AI Spec Instructions

## Overview
Ensure every AI-context template generated by `zeri generate` contains explicit guidance for creating new specifications using `zeri add-spec`. The messaging must be identical across Claude, Gemini, Codex/Agents, and Cursor instructions so assistants consistently follow the required specification workflow.

## Requirements
- Update `stubs/CLAUDE.md.stub`, `stubs/GEMINI.md.stub`, `stubs/AGENTS.md.stub`, and `stubs/cursor-zeri.mdc.stub` with clear directions to run `zeri add-spec <name>` when drafting new specs.
- Ensure the specification workflow text (create spec, plan, implement, mark TODO progress, review) is identical across every AI stub, including wording, ordering, and emphasis.
- Reinforce TODO best practices (detailed, actionable checklists with `- [x]` progress updates) identically within every AI stub.
- Add a shared instruction making it explicit that specifications must not be implemented unless explicitly requested and assistants should confirm the spec is complete and ready before coding.
- Include a critical reminder that TODO items must be marked as each implementation step finishes, rather than batching updates at the end, so assistants can resume accurately even with token or session limits.
- Preserve required references to `.zeri/` documentation files and avoid removing existing mandatory instructions.
- Provide automated coverage that the generated AI files contain the `zeri add-spec` message so regressions are caught.

## Implementation Notes
- Review current content in each stub to identify where to insert the shared instruction block.
- The Cursor template lives at `stubs/cursor-zeri.mdc.stub` and uses Markdown with Cursor-specific headings—keep structure intact while embedding the identical spec guidance block.
- `app/Commands/GenerateCommand.php` builds the AI files via generators; tests should exercise `php application generate all` (or targeted variants) to validate the stubs.
- Update or extend the existing feature tests in `tests/Feature/ZeriCommandsTest.php` (or add a new test file) to assert that the generated AI files mention `zeri add-spec` and that the shared block matches.
- When running integration tests for this spec, create a temporary project directory outside the repository (e.g., `../zeri-spec-test`) and invoke commands with `--path` so the primary project files remain untouched.
- After edits, regenerate AI files in a throwaway directory to manually confirm formatting before finalizing.
- Ensure the shared block keeps all actionable tasks in the dedicated TODO section only—no checklists or TODO phrasing should appear in Overview, Requirements, or Implementation Notes of the generated specification.
- Validate that the shared block explicitly tells AI assistants to confirm specification completeness and ask whether it is ready before attempting any implementation work.
- Confirm the shared block stresses real-time TODO updates (mark each item when finished) so progress survives AI token limits or session resets.
